Important design decision: focus on MLP
- We decided to focus compression experiments on MLP rather than attention.
- Reason:
  - MLP weights contain a large fraction of parameters.
  - MLP compression is easier to interpret as low-rank linear compression.
  - Attention has q/k/v/o interactions, softmax, and sequence-position effects,
    making it a messier first compression target.
- Attention can still be mentioned as future work or comparison, but the main
  project story should be MLP compression.

Important design decision: use MLP input, not output
- The project plan frames one layer as:
  y = phi(Wu), where u = Norm(x).
- r_u is meant to measure the representation spectrum of the input u seen by W.
- Therefore the compression signal should come from the input distribution to
  the weight matrix, not from the output after the matrix has already acted.
- Output rank is more circular:
  low output rank could come from low input rank, the weight collapsing
  directions, activation/gating effects, or all of these.
- For Qwen MLPs, post_attention_layernorm output is the clean MLP input u for
  gate_proj and up_proj.

Important design decision: centered covariance as main activation rank
- Initial activation-rank results used uncentered second moment X.T @ X / n.
- That gave very low ranks and traces that were hard to interpret.
- We decided to use centered covariance as the main activation-rank estimate:
  Cov(X) = E[x x^T] - E[x]E[x]^T.
- The script now accumulates sum(x) and sum(x x^T), not raw activations.
- CSV column effective_rank uses centered covariance eigenvalues.
- CSV column second_moment_effective_rank is retained only as a diagnostic.
- This matters: in the current run, centered effective rank is much higher than
  uncentered rank, showing the uncentered estimate was dominated by common
  directions.

Important design decision: use sigma squared for weight rank
- We decided to define the main weight effective rank from sigma_i^2 rather
  than sigma_i.
- Reason:
  - low-rank approximation error in Frobenius norm is governed by the tail of
    sigma_i^2, not sigma_i
  - this makes the weight diagnostic line up better with compression
  - it also matches the fact that activation spectra are already second-order
    quantities
- Consequence:
  - all older weight-rank averages and ranges in this note were computed with
    the earlier sigma_i-based definition and should be treated as stale until
    the weight-rank, merge, and plot scripts are rerun

Concise report framing:
We restrict compression experiments to MLP blocks because their linear structure
makes the connection between input representation rank and weight compression
direct. We estimate the effective rank of normalized MLP inputs and compare it
to the effective rank of MLP weight matrices. A large mismatch between low input
rank and high weight rank suggests potential overcapacity. We then test whether
layers with lower MLP input rank tolerate stronger low-rank compression.

Perplexity interpretation note:
- The current benchmark pipeline appears directionally reliable because:
  - the base Qwen3-0.6B perplexity on validation.txt is plausible for a small model
  - the compressed-model ordering is coherent
  - all runs use the same tokenizer, same split, and same evaluation pipeline
- However, very large perplexity values should be interpreted cautiously.
- Reason:
  - perplexity = exp(average_nll)
  - when a compressed model is badly damaged, small changes in average NLL can
    explode into very large perplexity differences
- Therefore:
  - the ranking between methods is meaningful
  - extremely large perplexity ratios are less meaningful than the underlying
    average NLL differences
- For reporting, it is useful to keep both:
  - average_nll
  - perplexity
- Recommended additional evaluation practice:
  - use validation.txt for development
  - use test.txt for final reported numbers
  - evaluate multiple alpha values, especially milder settings than alpha = 1.0
  - optionally add a small qualitative generation sanity check later

Decision update - 2026-04-22

Main diagnosis statistics for the next workflow revision:
- After further discussion, the two main diagnosis quantities are now:
  - MLP input centered effective rank
  - MLP output uncentered trace
- Intended interpretation:
  - MLP input centered effective rank is the intrinsic-dimensionality signal
  - MLP output uncentered trace is the residual-write importance signal
- Compression-allocation principle going forward:
  - allocation should respect both intrinsic dimensionality and importance
  - rank alone should not determine the layerwise allocation rule
- Important experimental scope decision:
  - for the main compression experiments, we still compress only:
    - mlp.gate_proj
    - mlp.up_proj
  - we do not expand the main intervention to mlp.down_proj yet
  - rationale:
    - the residual-write importance story conceptually includes the full MLP
      branch
    - but the current main compression setup remains cleaner and more justified
      if the intervention is still restricted to gate_proj and up_proj

Candidate allocation formula to test next:
- For each layer, start from its MLP input centered effective rank as the base
  target rank.
- Then scale that base rank by:
  - a global compression strength alpha
  - a trace-based protection factor derived from the layer's MLP output
    uncentered trace before residual addition
- Trace-based protection-factor definition:
  - take the logarithm of each layer's MLP output uncentered trace
  - normalize those log-trace values across layers to the interval [0, 1]
  - call the normalized value w for each layer
  - convert w into a softened protection weight using beta:
    - trace_weight = beta + (1 - beta) * w
- Proposed plain-language rule:
  - each layer's target rank equals:
    - centered_input_effective_rank
    - times alpha
    - times trace_weight
- Interpretation:
  - centered effective rank determines the layer's natural rank budget
  - normalized log output trace determines how much of that budget the layer
    should keep
  - alpha controls the overall compression level
  - beta controls the minimum fraction of rank every layer retains
- Intended qualitative behavior:
  - higher-output-trace layers keep more rank
  - lower-output-trace layers keep less rank
  - beta prevents the allocation from becoming too small in weak-output layers
- Important implementation note:
  - for fair comparison against uniform, the final integer layer ranks should
    still be adjusted to match the exact total rank budget of the uniform
    baseline

Correction note - 2026-04-22

Layer-skipping policy update after introducing trace-aware importance:
- After further discussion, we decided that stage-3 compression experiments
  should no longer skip any transformer layer by default.
- Reason:
  - now that MLP output uncentered trace is part of the diagnosis story, we do
    not want to hard-code a prior assumption that the first or final layer must
    always be protected from compression
  - instead, every layer should remain eligible for compression, and any
    protection should come from the allocation rule itself
- Current intended default behavior:
  - compress gate_proj and up_proj in all transformer layers
  - do not skip the first layer by default
  - do not skip the final layer by default
- The optional skip-first-layer flag may still remain available for ablations,
  but it is no longer the main policy.
